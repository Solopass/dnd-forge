# UI audit — 2026-11-25 (v1.09)

Click-through of the app at 1440×900 (laptop) and 375×812 (phone), in all three layouts (Beyond Classic, Unified Command, Modular Grid) as DM and as Player, plus a code scan. No JavaScript errors were thrown during any of it (the only console errors are the dev server's live-reload socket, see U8).

Labels: **broken** = does the wrong thing · **missing** = not there or not wired · **confusing** = works but hard to use or understand.
Each item says how it was checked. Fix order for phase 5: broken first, then missing, then confusing.

## Content & import (also roadmap items 3–4)

- [x] **C1 broken — the built-in SRD library never loads.** *Fixed 2026-11-25: now 731 monsters / 1,097 spells in the compendium; regression test `custom-content-loader.test.ts`.* `src/engine/custom-content-loader.ts:20` guards every `import.meta.glob` with `typeof import.meta.glob === 'function'`. Vite only rewrites `import.meta.glob(...)` *calls*, so at runtime that check is false and every loader is `{}`. Result: the 334 + 2024 SRD monsters, the SRD spells, magic items, equipment and features in `src/custom-content/` are never added to the compendium (and custom characters/themes/layouts there don't load either). Checked: in the running app `loadCustomRepoEntities()` returned 0 entities while the 2014 monster JSON holds 334 and `normalizeCustomEntity` accepts them; the compendium database holds 56 monsters and 462 spells in total. The README's "675 monsters / 658 spells / 3,154 entities" is not true in the app today. The guard was probably added for the Bun CLI tools, which have no `import.meta.glob`.
- [x] **C2 broken — Free5e sync creates 23 fake spells named "A", "B", "C" … "U".** The Free5e Markdown parser turns the alphabetical index headings into spells. They show up in the compendium search, the Add Spell dialog and the Level-Up wizard's spell picks, and can be added to a sheet. Checked in the database: 23 spells with one-letter names, source "Free5e (Solopass/free5e)". *Fixed 2026-11-25: sync skips `_X.md` index pages, the parser rejects link-only pages, and startup deletes the old junk; tests in `free5e-index-pages.test.ts`.*
- [x] **C3 confusing: duplicate entries across sources.** Cure Wounds appeared twice (Free5e and SRD 5.1), the 56 built-in pack monsters also exist in the SRD JSON. **Fixed (phase 5), replaced by the duplicates system (content/importers-dedupe):** source priority is a setting (Settings, Up/Down buttons, localStorage `dnd-forge-source-priority`), default Mine > SRD 2024 > SRD 2014 > Free5e. Exact duplicates (normalized name + category + ruleset; diacritics, punctuation and spaces ignored) show the highest-priority copy; the others are folded into it ("also in: ..." in the inspector and compendium rows, missing class lists / description / image filled from them); nothing is deleted. Near duplicates (same category, same name after removing a possessive prefix or a trailing note, or name similarity >= 0.85, and the same spell level / CR when both state one; ruleset 'homebrew' compares with every ruleset) are only flagged, in a Duplicates tab in the Packs/Compendium dialog (Keep one / Keep both / Merge, Undo, Show resolved; saved in the Dexie `dupDecisions` table, schema v4). Every importer shows an import preview first ("N new, M exact duplicates (will fold into X), K possible duplicates (review)", Import / Cancel); the Free5e auto-sync at startup skips the preview. Checked: unit tests (`compendium-dedupe.test.ts`, `importers.test.ts`), store tests (`duplicates-store.test.ts`), Dexie v3 to v4 upgrade test (`db-upgrade.test.ts`). The shipped SRD + built-in content has 5 near-duplicate groups, all weapon/armor/shield pairs such as Longsword / +1 Longsword. The UI itself (tab, preview dialog, Settings card) was not click-tested in a browser. **Magic variants (content/variants-and-fixes):** names like "+N X", "X +N", "X, +N" are variants of X and are never flagged as near duplicates of it (`magic-variants.test.ts` checks the shipped content: no group contains a variant any more, so those 5 weapon/armor/shield pairs are gone); "+N" weapon/armor/shield entries whose base item exists are hidden from search and Add Gear (not deleted), and sheet items with magicBonus / customName replace them (old saves migrate on load). The new select and name field in the item inspector were not click-tested in a browser.
- [x] **C4 broken — Level-Up spell choices aren't filtered by class.** The Artificer level-up offers Eldritch Blast (a warlock spell) next to the junk C2 entries. Likely Free5e spells lack class lists and pass the filter. Checked: Level-Up wizard button list. **fixed (phase 5): the pick filter is strict (`spellOnClassList`): spells with no class info are excluded from class-filtered picks (the "All classes" box still shows them), and Artificer has its own list (empty in the SRD) instead of "show everything". The Add Spell dialog's "castable only" filter uses the same rule. Tests: `LevelUpModal.spells.test.tsx`, `classes-and-presets.test.ts`.**
- [x] **C5 broken — importing a character JSON fails silently.** `CharacterManagerModal.tsx:120-128`: a malformed file, or valid JSON without `name`/`classes`, is ignored with no message. Should report to the status console why it was rejected. Checked: code. **fixed (phase 5): a rejected character JSON reports the reason (not valid JSON / missing name and classes) to the status console and a toast. Other silent catches are storage/clipboard fallbacks. Tests: `character-json.test.ts`, `CharacterManagerModal.import.test.tsx`.**
- [x] **C6 missing — `campaign-pack.json` 404 on every load** from `Solopass/free5e`. Harmless; Jake will add the file. Until then the app could skip the request when the repo has no pack. **fixed (phase 5): a 404 for the manifest is "no pack", remembered 7 days per repo/branch/path in localStorage so later syncs skip the request. Other errors are not remembered. Test: `campaign-pack-404.test.ts`.**
- [~] **C7 importers.** Status per importer (tests in `src/engine/__tests__/importers.test.ts` use synthetic text only):
  - App JSON + batch JSON: works; entries are accepted or rejected with a reason (unknown category, monster without monsterMeta, unusable character). Characters in the simple handbook shape (abilities, equipment/features/spells id lists) are now converted (before they were accepted and would have broken the sheet). Backgrounds and species are valid categories.
  - Markdown paste: fixed standard statblocks (AC/HP/CR/size/speed/saves/every attack and save action), spells (level, fields, save/damage/heal, slot cost), weapons and armor (armor was read as a monster); bold `**Key:**` lines; stable ids so re-pasting replaces.
  - 5e.tools / backup JSON: fixed spells (damage/heal/save/attack activities, slot cost, classes, casting fields), XGE no longer counted as 2024, baseitem lists; backup export -> import round trip is identical (tested, incl. duplicate decisions).
  - Free5e sync: spells now carry the slot cost and the engine's @spell formulas (the old @spell_dc / @spell_atk tokens were unknown to the engine); feats, weapons and armor tables parse; sync tested against mocked GitHub responses, not the live repo.
  - D&D Beyond PDF: only the field-to-character mapping is tested with synthetic fields; **needs a real DDB PDF to confirm**.
  - Bulk PDF -> statblocks (`content:convert --category monster`): the old path split a book by page and could not find statblocks; a new extractor (`statblock-extractor.ts`) reads them from noisy PDF text. `content:convert --category monster` on a PDF now uses it and prints found / clean / problem counts. Local-only run on one of the user's 5e monster books: 36 statblocks found, 32 parsed cleanly, 4 had no readable name in the PDF text.
  - GitHub repo sync / Push Pack: sync tested with mocked fetch; the push payload builder is unit-tested, no real push was made.
  - Content fixes (flag it, fix it, review it; any entry, imported or built-in): a separate Dexie layer (`contentFixes`, schema v5) of reviewable patches with a base hash, so re-imports and Free5e resyncs never remove them and a changed source entry marks the fix "needs re-review" instead of applying it. Checked by tests: engine (`content-fixes.test.ts`), v3/v4 to v5 upgrade (`db-upgrade.test.ts`), a store-level feature test (`content-fixes-store.test.ts`: propose, not applied, DM approves, add to sheet and cast with the fixed damage, resync, re-approve, revert, export/import, player proposal reaching the host over Live Table), and component tests for the editor and the Fixes tab (`ContentFixes.ui.test.tsx`). Not click-tested in a browser: the Report / fix button, the Fixes tab layout, the file export/import dialogs.

## DM tools

All ten DM Studio tabs render without errors (Party & Sync, Campaign Binder, World Clock, Loot & Shops, DM Screen, Party XP & Milestones, Improv, World Map, Soundboard, Tactical Battlemap). Checked working: NPC and tavern generators, +1 Hr clock, treasure roller, Give to PC, Distribute All GP, XP award, DM Screen dice, soundboard play/stop.

- [x] **D1 confusing — two money pools, unlabeled.** The Loot tab shows 404 GP, but "Buy (2g)" says "have 0 GP": the shop spends the *active character's* purse, the 404 GP is the party's. Label both and show the character's GP next to the shop. **fixed (phase 5): the Loot tab says "Party stash: N GP", the shop shows "<Character>'s purse: N GP", and the "Insufficient GP" log names whose purse. Tests: `DmTools.test.tsx`, `useSheetStore.test.ts`.**
- [x] **D2 confusing — "Award Total XP (Split)" ignores the encounter total shown right above it.** The tab says "Current Encounter Total: 0 XP" and the button awarded 450 XP from a separate number field. Pre-fill the field from the encounter, or label it. **fixed (phase 5): the XP amount starts at the encounter total (still editable, labelled), and the button says "Award N XP to the party (M each)". Test: `DmTools.test.tsx`.**
- [x] **D3 check — "Quick Demo: Spawn 2× Goblin" goblins count 0 XP.** After the quick demo the XP tab said 0 XP; goblins added through the Encounter Builder counted correctly (2 × 50 = 100 XP). Probably the demo goblins have no CR. **fixed (phase 5): root cause was fractional CRs, not the demo. SRD JSON stores CR 1/4 as "0.25" and the XP table only knew "1/4", so about 160 SRD monsters counted 0 XP everywhere. `crToXp` normalizes decimals and the encounter stores the fraction. Tests: `encounter-cr.test.ts`, `useSheetStore.test.ts`.**
- [x] **D4 confusing — Encounter Builder rows jump after staging.** Staging a monster inserts the staged list above the table, so the next "+ Stage" click lands on a different monster. **fixed (phase 5): the staged list now sits below the table, so rows never move. Test: `EncounterBuilderModal.stage.test.tsx`.**
- [x] **D5 tied to C1 — Encounter Builder offers 56 monsters** ("All Rules (56)"), because of C1. *Now 731.*
